# Notes App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android (Expo) note-taking app — Apple Notes-style text notes + ink sketch notes, pin, date, share as copy/Markdown/PDF — backed by a Node/Express + Prisma + Neon Postgres API with email+password auth that stays signed in.

**Architecture:** Two packages under `notes-app/`: `api/` (Express + Prisma, cloned from the proven `vehicle-service-tracker/apps/api` patterns but standalone, not in that monorepo) and `mobile/` (Expo + expo-router + TypeScript). Auth is JWT access (15m) + opaque rotating refresh token (30d) stored in `expo-secure-store`; the client silently refreshes on launch so there is no login screen after first sign-in. Notes live in Postgres; sketch PNGs are stored as bytes in a sibling `NoteImage` table (no external object store needed for v1).

**Tech Stack:** API — Express 4, Prisma 6, `@node-rs/argon2`, `jsonwebtoken`, `zod`, `vitest` + `supertest`. Mobile — Expo (latest SDK), `expo-router`, `@10play/tentap-editor` (rich text), `@shopify/react-native-skia` (ink), `expo-secure-store`, `expo-clipboard`, `expo-print`, `expo-sharing`, `expo-file-system`.

**Spec:** `notes-app/docs/2026-10-30-notes-app-design.md`

## Global Constraints

- Backend database: Neon Postgres (Prisma `postgresql`, `DATABASE_URL` pooled + `DIRECT_URL` for migrations), copied verbatim from the sibling repo's datasource block.
- Auth values copied verbatim from sibling: access TTL `15m`, refresh TTL `30` days, argon2id `{ memoryCost: 19456, timeCost: 2, parallelism: 1 }`, auth rate limit `5` per `15 min` keyed on `ip:email`.
- Identity is **email** (lowercased, trimmed), not phone. No phone, no `recoveryPhone`, no password reset (v1 non-goal).
- Note title is the first line of the body, set by the client on save; never a user-edited field.
- A note is `kind` `'text'` or `'sketch'` — never both. Text notes carry `bodyHtml`; sketch notes carry a `NoteImage`.
- List order: `isPinned desc`, then `updatedAt desc`.
- Sketch images: PNG only, `<= 4 MB`, one per sketch note.
- Deliverable: EAS internal-distribution APK (`eas build -p android --profile preview`), not a Play Store release.

## Review Focus

- **Empty note body** → saving a note whose body is blank must not crash; title falls back to `"Untitled"`. (Task 3 test.)
- **Cross-user access** → user B requesting user A's note id (GET/PATCH/DELETE/image) must get 404, never A's data. (Task 3 + Task 4 tests.)
- **Expired access token mid-session** → a 401 `TOKEN_EXPIRED` from any call triggers one silent refresh-and-retry; a failed refresh routes to login. (Task 5 test on the client interceptor.)
- **Oversized / non-PNG sketch upload** → >4MB or wrong content-type is rejected 413/415, not stored. (Task 4 test.)
- **HTML with lists/headings → plain text & Markdown** → share helpers must turn `<ul>/<ol>/<h1>` into readable text and correct Markdown, not leave tags. (Task 9 test.)

model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
  sessions     Session[]
  notes        Note[]
}
model Session { // copy sibling Session verbatim }
model Note {
  id        String    @id @default(cuid())
  userId    String
  kind      String    @default("text") // "text" | "sketch"
  title     String    @default("Untitled")
  bodyHtml  String?   // text notes
  isPinned  Boolean   @default(false)
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt
  user      User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  image     NoteImage?
  @@index([userId, isPinned, updatedAt(sort: Desc)])
}
model NoteImage {
  noteId   String @id
  bytes    Bytes
  mimeType String @default("image/png")
  note     Note   @relation(fields: [noteId], references: [id], onDelete: Cascade)
}

### Task 3: Notes CRUD, pin, ordering, isolation

**Files:**
- Create: `notes-app/api/src/routes/notes.ts`

**Interfaces:**
- Consumes: Task 1–2.
- Produces: `notesRouter`. Routes (all `requireAuth`, all scoped by `userIdOf(req)`):
  - `GET /api/notes` → `Note[]` without `bodyHtml` large payloads is fine to include; order `isPinned desc, updatedAt desc`. Each item: `{ id, kind, title, isPinned, hasImage, createdAt, updatedAt }` (no body in the list — fetch body on open).
  - `POST /api/notes` body `{ kind, bodyHtml? }` → created note. `title` = `deriveTitle(bodyHtml)`.
  - `GET /api/notes/:id` → full note incl. `bodyHtml`; 404 if not owned.
  - `PATCH /api/notes/:id` body `{ bodyHtml? }` → updates body, re-derives `title`, bumps `updatedAt`; 404 if not owned.
  - `PATCH /api/notes/:id/pin` body `{ isPinned }` → updates pin; 404 if not owned.
  - `DELETE /api/notes/:id` → 204; 404 if not owned.
- `deriveTitle(html?: string): string` in `src/lib/title.ts` — strip tags, first non-empty line trimmed to 80 chars, else `"Untitled"`.

Every `:id` query uses `where: { id, userId }` (sibling's ownership pattern) so another user's id is a 404.
